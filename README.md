# 動画生成スタジオ — 確定仕様・運用ガイド

公開の画面専用リポジトリ `video-generator-ui` をGitHub Pagesで配信し、非公開の `MasayukiYamakura/video-generator` で動画を生成します。iPhoneのSafari向けです。

## 初回設定

1. 公開リポジトリへ `index.html`、`style.css`、`app.js`、`builder-entry.js`、`builder/`内の全MJS、本README、`.nojekyll` を配置します。
2. Settings → Pages → Deploy from a branch → main / root を選びます。
3. 非公開リポジトリに `.github/workflows/generate_video_ui.yml` と `scripts/ui_job.py` を配置します。
4. GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens で、非公開 `video-generator` だけを対象にトークンを発行します。Repository permissions は Contents: Read and write / Actions: Read and write。Metadataは自動付与。公開リポジトリやWorkflowsの書込権限は不要です。
5. PagesをSafariで開き、接続設定にトークンを入力して接続確認します。トークンをチャットへ送る必要はありません。

公開ソースに認証情報を埋め込まないでください。トークンの永続保存は初期状態でオフです。「この端末に保存」を選ぶとlocalStorageに保存され、同一オリジンのスクリプトから読めます。信頼できる自分の端末だけで使い、同じユーザーのPagesに不審なコードを置かないでください。「接続情報を削除」でトークンを消し、履歴は保持します。

## 毎回の操作

1. iPhoneのボイスメモを共有 →「ファイルに保存」。
2. 音声を選択。20 MiB以下、m4a / mp3 / wav / aac / ogg / flac / mp4 / aiff / aif。拡張子対応であり、内部の不正な形式は生成時に失敗します。
3. JSONを貼り付けるかファイルから読込み。1 MiB以下、空ではないscenes配列が必要です。
4. 動画生成を押し、**実行受付完了までSafariを前面に保つ**。
5. 受付後は画面消灯、別アプリへの移動が可能。GitHub Actionsで処理が続きます。
6. 同じURLへ戻ると状態を更新。タブが再読み込みされた場合もlocalStorageの履歴を復元します。ブラウザデータ削除やプライベートブラウズでは履歴が消える場合があります。
7. 完了後「動画をダウンロード（ZIP）」を押す。GitHubへのログインが必要な場合があります。「ファイル」でZIPを開きMP4を取り出します。直接MP4保存は初版対象外です。

## 入力と生成

画面は選んだ音声を `input.<拡張子>` に紐付けるため、送信するJSONのaudio_fileだけを書き換えます。画面に貼ったJSON自体は保持します。Prompt Builderの画面設定適用がOFFなら、音声加工や動画レイアウトなど他の設定は変更しません。ONならプロンプト生成時の確定設定を合成して送ります。固定人物画像・アイコン・ローカル動画は現行リポジトリのmediaに配置済みのものを使います。初版では画像のアップロード機能を追加しません。

受付IDごとに親のない入力専用コミットと `ui-input/<UUID>` 一時ブランチを作り、音声・JSONだけを保存します。mainには録音をコミットしません。workflowはmainの信頼できる生成コードを実行し、入力ブランチのコードやworkflowを実行しません。SHAで入力を固定し、生成前にブランチのSHAを確認します。

Pages専用経路ではDrive検索を無効にし、アップロードした台本・録音と既存media素材を使用します。既存の手動workflowは変更せず、従来のDrive利用は引き続き可能です。

## 状況・復元・重複防止

入力確認中／アップロード中／実行依頼中／待機中／処理中／完了／失敗／キャンセルを表示します。取得できる現在のworkflow工程を表示し、正確な進捗率・残り時間は表示しません。実行詳細へのリンクを付けます。

受付ID・入力SHAは送信前に端末へ保存します。通信断の際は「受付状況を確認」を押し、見つからなければ同じIDで再送できます。生成依頼を送った可能性がある入力は自動破棄しません。送信前に失敗した入力は「未受付の入力を取り消す」で取り消せます。

同じ受付IDは `ui-accepted-<UUID>` の軽量タグを原子的に作成して一度だけ生成します。タグは音声ではなく生成コードのコミットを指します。重複依頼・Actionsの再実行で動画を再生成しません。失敗時に作り直す場合は、新しい生成操作で新しい受付IDを発行します。

画面からの生成は1件ずつ。同じブラウザの連打を防ぎ、GitHub側も専用concurrencyで直列実行します。別端末が同時に操作した場合、待機が生じることがあります。履歴は直近50件、受付検索は最大500実行です。

状態取得は前面表示中に約15秒間隔。戻ったときと更新ボタンでも取得します。認証期限切れ・権限不足を表示します。トークンを保存しない場合、再読み込み後は再入力が必要です。

## 保存期間・費用

成果物名は `video-<受付ID>`、内容はoutput.mp4、保存期間は3日です。削除・期限切れ・成果物なしを表示します。履歴から該当成果物にリンクします。

生成成功・失敗後、入力SHAが変わっていない一時ブランチを削除します。強制キャンセル、準備前の失敗、通信断などでは残る場合があります。不要な `ui-input/` ブランチは内容を確認してGitHubで削除できます。Gitの到達不能オブジェクトはGitHub側の回収まで残り、ブランチ削除による即時の容量解放は保証しません。重複防止タグは保持します。

有料サービスは追加しません。Pagesの常時公開はActionsの動画生成時間を消費しません。非公開側のActions実行時間・成果物・キャッシュには無料枠が適用されます。無料枠の範囲内に収まること自体は保証しません。失敗時に自動生成を繰り返しません。

## 公開するもの

HTML / CSS / JavaScript / READMEのみ。音声・JSON・動画・トークン・APIキーは公開側に配置しません。公開ページは認証画面でアクセス制限されたサイトではなく、非公開GitHub APIへの操作だけがトークンで保護されます。外部JS・解析サービス・CDNを使いません。

## 検証と運用上の限界

公開前にJavaScript・Python構文、入力検証、復元、GitHub APIモック、重複拒否、SHA変更拒否を検証します。公開後はiPhone実機で音声選択 → 実行受付 → 消灯 → 再訪 → ZIPダウンロードを確認します。ブラウザでの自動テストだけではiOSの画面消灯動作まで保証できません。

## 対象外

自動文字起こしからのJSON作成、AIによる台本作成、TikTok投稿、MP4直接保存、プッシュ通知、動画の画面内プレビュー、画像アップロード、複数ユーザー向けサービス。動画／レイアウトの設定フォームはPrompt Builderとして追加済みです。


## BGM設定の確認

Prompt Builderでは「保存済み設定を読込」後、「今回の設定」でBGMの選択方式・曲に加え、音量（標準から-30〜+24 dB）と「発話中にBGM音量を下げる」を調整できます。0 dBは無音ではなく標準音量です。標準は声-16 LUFS、BGM-32 LUFSで、ダッキングONでは発話中さらにBGMが下がります。+6 dBでも小さい場合は、ダッキングOFFで+12→+18 dBの順に調整できます（最大+24 dB）。声が聞き取れる音量に調整してください。標準値は変更していません。設定変更後はプロンプトを再生成してください。音量・ダッキングは動画プリセットとして保存できます。

タイトルの改行を確実に指定する場合は「AI設定 → フック文章 → 手動」で、表示したい行のまま入力します。1つのタイトル内部の改行と、複数タイトルの区切り（改行 --- 改行）は別です。「画面設定をJSONへ適用」または送信時の適用で、AIが改行を削除しても手動タイトルを再適用します。録音照合用のtextとタイトル表示用のhook_textは別で、タイトルの改行はhook_textに必要です。

台本JSONの `global_settings.bgm` をそのまま送信します。「BGM設定を確認」で非公開リポジトリの `media/bgm/catalog.json` を読み込み、予定曲と音量を表示します。生成後は履歴に実際の曲名と音量を表示し、ZIPの `bgm-report.json` に詳細を記録します。音源と利用条件の登録方法は動画生成リポジトリのREADME「登録済みBGMを動画に組み込む」を参照してください。5カテゴリ各1曲のCC0音源を登録済みです。BGM設定なしのJSONは従来どおり動作します。



## Prompt Builderの操作

画面上で「動画プリセット」「レイアウトプリセット」「今回の設定」「AI設定」を選び、プロンプトを生成・コピーできます。AI APIへの接続は行いません。

1. 保存済み設定を読込（GitHub接続欄のトークンを使用）。プリセットとBGM登録一覧は非公開側から取得します。
2. TikTok標準／TikTok匿名音声／TikTok縦書きフック／YouTube横型から選択。匿名は標準のvoiceだけを変更する継承です。
3. 必要なら背景、BGM OFF／AIカテゴリ／手動カテゴリ／曲指定、フック方向、冒頭／本編のタグ・波形・字幕を変更。
4. レイアウト調整でタグ左上x/y、波形中心x/y・size・表示幅、フック／字幕の位置・サイズ・幅・帯不透明度を変更。簡易プレビューと縦型の右17%／下18%ガイドで確認。ガイドは動画に描画しません。
5. フック・素材検索語・動画挿入シーン・横型テーマをAI自動または手動指定。シーン分割はAIです。
6. 台本を入力し、プロンプト生成 → コピー → AIへ貼る → AI返答をscript.json欄へ貼る。
7. 「画面設定をJSONへ適用」で確認し、音声を選んで動画生成。

プロンプト生成時に確定設定のスナップショットを保持します。設定を変えると無効化するため、再生成してください。「送信時に画面設定を適用」ONでは送信前にも確定値を適用し、AIのglobal_settings、シーンの表示・位置・スタイルによる上書きを防ぎます。従来のJSONを変更せず使うときはOFFにします。

「script.json全体」は従来方式、「内容だけ」はscenesと必要なbgm_category／theme_titleだけをAIから受け取り、画面で確定設定を合成する方式です。どちらも既存workflowへ送信します。

### 設定と保存

動画プリセットは意味・表示・素材方針、レイアウトは座標・大きさ、毎回設定はoverride、AI設定は判断方式です。内部描画・音声加工値は通常UIに出しません。優先順位は手動override > レイアウト > 動画 > AIの許可スロット > 初期値。動画プリセットに座標は保存できません。

ID・表示名を入力し、動画／レイアウトの各保存ボタンで選択元からの差分を保存します。ユーザー定義は非公開リポジトリmainの `config/prompt-builder.json` に記録し、次回の読込で再利用します。元の定義と同じIDへの上書きは拒否します。別端末の変更はSHAで保護し、競合時は再読込が必要です。保存でActions動画生成を実行しません。favorites配列は将来用で、全設定お気に入りUIは未実装です。

画像と推奨レイアウトは `backgrounds:[{id,name,file,recommended_layout}]` で対応できます。ファイルはmedia内のPNG/JPEG/WebP。登録自体は非公開JSONを編集し、画面で選択・「推奨レイアウトを適用」で反映します。背景の変更だけでは位置overrideを上書きしません。

### 配信順序・互換性

非公開video-generatorの描画変更を先にmainへマージし、その後このUIの変更を公開リポジトリへ反映してください。公開するのはHTML/CSS/JS/MJS・READMEのみ。非公開プリセットJSON、BGM一覧、録音、画像、台本を公開側へコピーしません。トークンは既存接続欄を利用し、Builderの設定へ保存しません。

フックorientation未指定の旧JSONは、人物画像テンプレートでは横書き・通常テンプレートでは縦書きのままです。Pexels／Pixabay動画のタグ非表示・Pexels波形非表示を維持します。背景画像は既存ファイルを参照し、中央cropは変えません。ドラッグ調整、タグサイズ／間隔、背景zoom、実動画プレビュー、全設定お気に入りは今回追加しません。

簡易プレビューの折り返し・フォント・波形は実動画と完全には一致しません。設定値は正確にJSONへ反映します。再読込後はトークン（端末保存OFF時）とプロンプト生成が再度必要です。モバイル幅の連携はAPIモックでテストしますが、iPhone実機Safariのコピー・消灯後復元は公開後に確認してください。




## AI読み上げ

上部のナレーション原稿からPrompt Builderでプロンプトを作り、AIのJSONを確認して送信します。音声方式は録音／匿名加工／AI読み上げです。AI読み上げでは音声ファイル不要。声（本人・男性A/B）、話し方、速さ、任意の詳細設定を指定します。APIキー・Voice IDは非公開の生成リポジトリのSecretsへ登録し、公開UIへ記載しません。本人Voiceが未登録なら男性A/Bを選択してください。Backend PRを先にマージしてから公開UI PRをマージします。初回は短い原稿で音声と字幕を確認してください。



## BGM登録・試聴・冒頭タイトル調整（2026-10-09）

「BGMを追加」でMP3/M4A/WAV/OGG/FLAC（20 MiB以下）、曲ID、曲名、作者、カテゴリ、出典URL、ライセンス、商用利用確認、クレジット要否を入力します。URLは出典記録用で、YouTube Audio Libraryからの自動取得は行いません。音源とcatalog.jsonを非公開リポジトリmainへ1コミットで保存します。ID・音源の重複とmainの更新競合は登録を止めます。登録だけでActionsは起動しません。音源の実際のデコードは試聴生成・本番生成時にFFmpegで検証します。

「今回の設定」のBGM設定では「曲のどこから使うか」と「動画の何秒目から流すか」を別々に指定します。例えば曲30秒・動画3秒なら動画の3秒目から曲の30秒目を使います。動画開始位置は動画尺より前、曲開始位置は音源末尾より前にしてください。フェードインはBGMの再生開始時点から適用されます。ループ・フェード秒も画面から指定でき、動画プリセットに保存できます。

JSONを貼り付け、画面設定を適用した後「音声＋BGMを試聴用に生成」を押します。添付録音／匿名加工が対象で、TTS試聴は対象外です。字幕タイミングと本番の書き出し尺を計算し、同じDSP・正規化・ダッキング・フェード・ピーク制限でミックスします。動画描画は行いませんが、Actionsの時間を使います。完了後は画面内プレーヤー、または履歴の「画面で確認」で再生できます。AAC圧縮や再生機器により聞こえ方は変わり得ます。

同じ添付音声と設定が維持されているとき、本番のBGMは試聴曲IDに固定し音源のSHA-256を検証します。設定や音声を変更した場合は再試聴してください。「AI」は外部のChatGPT/Geminiが原稿に合うカテゴリを提案する意味です。カテゴリ内は優先順位・曲ID順で選び、AIが曲を聴き比べる機能ではありません。

レイアウト調整の「帯の色」「帯の横幅比率」「帯の上下余白」「フック最大文字サイズ」「文字サイズ方式」を設定できます。自動調整は指定サイズが上限、固定サイズは収まらない場合にエラーにします。帯の幅と文字最大幅は別の設定です。これらは横書き冒頭フックに適用し、左上の横型テーマとは別です。レイアウトプリセットに保存できます。

簡易プレビューは手動フック文章、またはJSON先頭シーンのhook_textを改行込みで表示します。「冒頭をプレビュー」をONにしてください。「正確なタイトル静止画を生成」は本番の日本語フォントとタイトル描画を使用します。先頭シーンの横書きフックのみを確認し、固定背景の切り出し・黒フィルターを反映します。外部動画、タグ、波形、通常字幕は静止画に含めません。

試聴音声・静止画は非公開の親なしui-preview/<受付ID>ブランチから認証付きで読み込みます。公開UIへ素材をコピーしません。「試聴結果を削除」でこのリポジトリの完了済みプレビューの結果ブランチを削除できます。3日より古い結果ブランチは次のプレビュー完了時にも削除します（時刻ちょうどの削除ではありません）。ZIPのArtifact保存期間は3日です。ブランチ削除でGitHub内のデータの即時完全消去は保証されません。


## 手動フックのプレビュー・AI動画割合

手動フック文章に入力があれば、判断方式にかかわらず簡易プレビューへ優先表示します。入力時は冒頭プレビューがONになります。改行を保持し、複数フックでは最初のタイトルを表示します。生成に手動タイトルを使用する場合はフック文章を「手動」にしてください。

「人物画像から動画に切り替えるシーン」がAI自動の場合、「AI自動の動画シーン割合」を0〜100%の整数で指定できます（初期値10%）。人物画像＋一部動画の場合に適用し、シーン数に対する割合をAIプロンプトへ反映します。時間の割合ではありません。AIが挿入箇所と検索語を判断するため、返されたJSONの挿入数は確認してください。手動の場合はシーン番号の指定を優先します。
