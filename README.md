# 動画生成スタジオ — 確定仕様・運用ガイド

公開の画面専用リポジトリ `video-generator-ui` をGitHub Pagesで配信し、非公開の `MasayukiYamakura/video-generator` で動画を生成します。iPhoneのSafari向けです。

## 初回設定

1. 公開リポジトリへ `index.html`、`style.css`、`app.js`、本README、`.nojekyll` を配置します。
2. Settings → Pages → Deploy from a branch → main / root を選びます。
3. 非公開リポジトリに `.github/workflows/generate_video_ui.yml` と `scripts/ui_job.py` を配置します。
4. GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens で、非公開 `video-generator` だけを対象にトークンを発行します。Repository permissions は Contents: Read and write / Actions: Read and write。Metadataは自動付与。公開リポジトリやWorkflowsの書込権限は不要です。
5. PagesをSafariで開き、接続設定にトークンを入力して接続確認します。トークンをチャットへ送る必要はありません。

公開ソースに認証情報を埋め込まないでください。トークンの永続保存は初期状態でオフです。「この端末に保存」を選ぶとlocalStorageに保存され、同一オリジンのスクリプトから読めます。信頼できる自分の端末だけで使い、同じユーザーのPagesに不審なコードを置かないでください。「接続情報を削除」でトークンを消し、履歴は保持します。

## 毎回の操作

1. iPhoneのボイスメモを共有 →「ファイルに保存」。
2. 音声を選択。20 MiB以下、m4a / mp3 / wav / aac / ogg / flac / mp4 / aiff / aif。拡張子対応であり、内部の不正な形式は生成時に失敗します。
3. JSONを貼り付けるかファイルから読込み。1 MiB以下、空ではないscenes配列が必要です。
4. 動画生成を押し、**実行受付完了までSafariを前面に保つ**。
5. 受付後は画面消灯、別アプリへの移動が可能。GitHub Actionsで処理が続きます。
6. 同じURLへ戻ると状態を更新。タブが再読み込みされた場合もlocalStorageの履歴を復元します。ブラウザデータ削除やプライベートブラウズでは履歴が消える場合があります。
7. 完了後「動画をダウンロード（ZIP）」を押す。GitHubへのログインが必要な場合があります。「ファイル」でZIPを開きMP4を取り出します。直接MP4保存は初版対象外です。

## 入力と生成

画面は選んだ音声を `input.<拡張子>` に紐付けるため、送信するJSONのaudio_fileだけを書き換えます。画面に貼ったJSON自体は保持します。音声加工や動画レイアウトなど他の設定は変更しません。固定人物画像・アイコン・ローカル動画は現行リポジトリのmediaに配置済みのものを使います。初版では画像のアップロード機能を追加しません。

受付IDごとに親のない入力専用コミットと `ui-input/<UUID>` 一時ブランチを作り、音声・JSONだけを保存します。mainには録音をコミットしません。workflowはmainの信頼できる生成コードを実行し、入力ブランチのコードやworkflowを実行しません。SHAで入力を固定し、生成前にブランチのSHAを確認します。

Pages専用経路ではDrive検索を無効にし、アップロードした台本・録音と既存media素材を使用します。既存の手動workflowは変更せず、従来のDrive利用は引き続き可能です。

## 状況・復元・重複防止

入力確認中／アップロード中／実行依頼中／待機中／処理中／完了／失敗／キャンセルを表示します。取得できる現在のworkflow工程を表示し、正確な進捗率・残り時間は表示しません。実行詳細へのリンクを付けます。

受付ID・入力SHAは送信前に端末へ保存します。通信断の際は「受付状況を確認」を押し、見つからなければ同じIDで再送できます。生成依頼を送った可能性がある入力は自動破棄しません。送信前に失敗した入力は「未受付の入力を取り消す」で取り消せます。

同じ受付IDは `ui-accepted-<UUID>` の軽量タグを原子的に作成して一度だけ生成します。タグは音声ではなく生成コードのコミットを指します。重複依頼・Actionsの再実行で動画を再生成しません。失敗時に作り直す場合は、新しい生成操作で新しい受付IDを発行します。

画面からの生成は1件ずつ。同じブラウザの連打を防ぎ、GitHub側も専用concurrencyで直列実行します。別端末が同時に操作した場合、待機が生じることがあります。履歴は直近50件、受付検索は最大500実行です。

状態取得は前面表示中に約15秒間隔。戻ったときと更新ボタンでも取得します。認証期限切れ・権限不足を表示します。トークンを保存しない場合、再読み込み後は再入力が必要です。

## 保存期間・費用

成果物名は `video-<受付ID>`、内容はoutput.mp4、保存期間は3日です。削除・期限切れ・成果物なしを表示します。履歴から該当成果物にリンクします。

生成成功・失敗後、入力SHAが変わっていない一時ブランチを削除します。強制キャンセル、準備前の失敗、通信断などでは残る場合があります。不要な `ui-input/` ブランチは内容を確認してGitHubで削除できます。Gitの到達不能オブジェクトはGitHub側の回収まで残り、ブランチ削除による即時の容量解放は保証しません。重複防止タグは保持します。

有料サービスは追加しません。Pagesの常時公開はActionsの動画生成時間を消費しません。非公開側のActions実行時間・成果物・キャッシュには無料枠が適用されます。無料枠の範囲内に収まること自体は保証しません。失敗時に自動生成を繰り返しません。

## 公開するもの

HTML / CSS / JavaScript / READMEのみ。音声・JSON・動画・トークン・APIキーは公開側に配置しません。公開ページは認証画面でアクセス制限されたサイトではなく、非公開GitHub APIへの操作だけがトークンで保護されます。外部JS・解析サービス・CDNを使いません。

## 検証と運用上の限界

公開前にJavaScript・Python構文、入力検証、復元、GitHub APIモック、重複拒否、SHA変更拒否を検証します。公開後はiPhone実機で音声選択 → 実行受付 → 消灯 → 再訪 → ZIPダウンロードを確認します。ブラウザでの自動テストだけではiOSの画面消灯動作まで保証できません。

## 対象外

自動文字起こしからのJSON作成、AIによる台本作成、TikTok投稿、MP4直接保存、プッシュ通知、動画の画面内プレビュー、画像アップロード、JSON設定フォーム、複数ユーザー向けサービス。


## BGM設定の確認

台本JSONの `global_settings.bgm` をそのまま送信します。「BGM設定を確認」で非公開リポジトリの `media/bgm/catalog.json` を読み込み、予定曲と音量を表示します。生成後は履歴に実際の曲名と音量を表示し、ZIPの `bgm-report.json` に詳細を記録します。音源と利用条件の登録方法は動画生成リポジトリのREADME「登録済みBGMを動画に組み込む」を参照してください。初期状態は音源未登録です。BGM設定なしのJSONは従来どおり動作します。
